## 痛点
原始figma MCP提取到的yaml经过压缩，排去冗余信息交给LLM，通过prompt让内置模型去识别组件，但是简化之后的yaml只能描述模块对应的形状。导致LLM 组件识别不稳 ：Button / Tag / Table / Filter / Metric Card 全靠模型自己猜，同一份图不同轮次结论都能变，并且很难命中正确组件。
LLM面对问题：
- 要在图形学 type 上做语义抽象 ：认出"FRAME + RECTANGLE(圆角) + TEXT"是 Button；
- 要识别多节点的组合模式 ：认出"三段 TEXT + VECTOR" 是 MetricCard；
- 要判断重复结构 ：认出 20 个几乎一样的 FRAME 应该合成一个 Table 或 List；
- 要对齐设计系统命名 ：把上面识别的东西对应到 m4b 具体的组件名（比如 m4b 内部叫 MetricGroup 还是 KpiCard ）；
- 要处理设计师随手起的中文/拼音/乱码 name ：从 name 抓语义提示但又不能盲信。

这里的每一步都是"猜" ——不是模型不够聪明，而是 这些语义本来就不在 Figma 数据里 ，得从视觉结构模式里推断，加上大量 domain knowledge 才对。表现出来的问题就是：

- 每轮结果不稳定 ：同一份 Figma 让 LLM 跑两次，结果里可能一次是 Button 一次是 Tag。
- 假阳性 / 假阴性 都常见 ：看到圆角 + 文字就以为是 Button（其实是 Badge）；看到 Table 结构以为是普通 List。
- 命名飘 ：m4b 明明叫 MetricCard ，模型输出 KpiCard / IndicatorBox / StatBlock 各种花名。
- 上下文越大越飘 ：YAML 5000 行以上，模型注意力衰减，越靠后的组件越离谱。
- 不同 design system 无法复用 ：换到 hiui，"m4b 的规则"全废，等于全靠 prompt 重新教。

## 解决方案
所期待的组件语义实际上应该由"type + 布局 + 尺寸 + 节点的重复关系 + 文本 + icon" 组合而成
设计打分专家系统，递归遍历yaml树，从子节点开始打分，依次向上回归为父节点打分，给出每一层节点的组件候选，最终输出YAML，再由 外部的 D2C runner 转成真正的代码提供给下一层继续处理


专家系统 = 声明式组件签名库 + 前序 DFS 打分 + 父抑制子 ：

1. 前置归一化 ：Figma 原始 JSON 经过 simplifyRawFigmaObject + SVG 折叠 + 重复结构归一化，压成一棵 FigmaLikeNode 简化树。
2. 前序 DFS 打分 ： walkNode 从根开始 DFS，对每个节点独立跑 67 个组件签名的加法打分（ nameHints +0.30 / componentNameHints +0.35 / childNameHints +0.10 / layoutHints +0.05 / structureMatchers +0.25 / structureRules +0.20），再叠加"强信号短路"到 0.9x 封顶。
3. 三段阈值 ： >=0.7 进 debugNodes， >=0.9 进 matchedNodes。
4. 父抑制子 ：先做 同节点内互斥 （Table 吃掉自己身上的 Pagination 候选），再做 跨节点祖先-后代互斥 （Table 祖先把后代里的 Pagination/Select/Empty 抹掉）。
5. 产物 ： { figmaNodeData: YAML树, candidateComponents, candidateNodes, candidateDebugNodes, rootBounds, ... } 。
6. 主推断工具 ： figmaToM4bComponents 把上面产物 + 图 URL + metrics 拼成 prompt 交 LLM，让 LLM 在 限定候选里选择组件 + 补全 props ，输出 m4b 组件 YAML（ m4bYamlResult ）。
7. 代码生成 ：Mastra 层到 YAML 就结束，YAML → JSX/TSX 由 下游 D2C runner （apps/agents、spec-server、CI 等）承接，可能把结果作为 codeArtifacts 回填缓存供下次直接命中。
一句话核心： 专家系统靠可插拔的签名库把 Figma 图形层反推成"限定候选组件"，把 LLM 从"开放识别"降级到"选择题 + 属性补全" ，从而拿到稳定性、成本、可运营性上的收益。


## 实际内容
1) 每个组件都有一份「签名」
```ts
{
  name: 'Button',
  detect: {
    nameHints: ['button', 'type=ai', ...],
    componentNameHints: ['Button', 'Light button', 'Dark button', ...],
    childNameHints: ['Text', 'Text Label', 'label', ...],
    structureRules: [
      { kind: 'hasMinChildren', value: 1 },
      { kind: 'hasComponentNames', anyOf: ['Light button', 'Dark button'] },
    ],
    structureMatchers: ['triggerArea'],
    layoutHints: ['row'],
  },
  containsTargets: ['Tag', 'Link'],   // 我是 Button 的话，别再往下认成 Tag / Link
  mapping: {...},                     // 后续 LLM 用来做属性映射
  omitDefaults: [...],                // 输出层的默认值处理
  misDetectionRules: [...],           // 反例，训练时给模型看
}
```

六种识别信号 （ FigmaStructureRule.kind ）：
hasNamedChildren  | hasPropNames    | hasPropValues
hasComponentNames | hasMinChildren  | hasLayoutMode

2) 节点门槛：不是所有节点都参加打分
- TEXT类型 节点直接跳过 （文字不是组件）
- isDividerSvgSignal （细长的分割线状 SVG/Line/Rectangle） 特殊放行 ——因为 Divider 恰恰是一个 SVG
- 其他 IMAGE-SVG / VECTOR 图元节点跳过 （除非上面那种）
- 有 children 的节点参加打分
- 空节点但带 componentId 或 componentProperties 也参加（可能是 INSTANCE / 变体）

3) 基础打分：加法制，最高 1.0

`scoreSingleSignature` 里对每个 signature 依次加分：

| 触发条件 | 加分 | reason |
|---|---|---|
| 节点自己的 `name` 命中 `nameHints` | **+0.30** | `node name matched` |
| INSTANCE 的 `component name` / `componentSet name` 命中 `componentNameHints` | **+0.35** | `component name matched` |
| 直接子节点 `name` 命中 `childNameHints` | **+0.10** | `child name matched` |
| 子节点 auto-layout 方向命中 `layoutHints` | **+0.05** | `layout matched` |
| 命中任一个 `structureMatchers`（函数式判断） | **+0.25** | `structure matched` |
| 全部 `structureRules` 都通过（AND 关系） | **+0.20** | `structure rule matched` |

4) 强信号短路：`Math.max(score, 0.9x)` 一票封顶

| 组件 | 强信号 | 封顶 |
|---|---|---|
| **Table** | `headerRowWithMultipleBodyRows` | **0.92** |
| **Dropdown.Button** | 名字含 `more` / `…` / `down`，或 icon 名是 `iconmore` | **0.92** |
| **Button (AI)** | 名字含 `button` + AI type / state / border activation | **0.92** |
| **Container (AI)** | 含 `surface=ai` / `ai surface animation - card` | **0.95** |
| **DatePicker 家族** | date picker signal + AI activation → 按 `period=week/month/quarter/year/range` 分 6 种子类型 | **0.94** |
| **TimePicker** | time picker + AI activation | **0.94** |
| **Modal (self-named)** | 节点名 / component 名 = `modal` 或 `modal/*` | **0.96** |
| **Drawer (self-named)** | 同上，component = `drawer` | **0.96** |
| **Avatar (self-named)** | 名字含 `avatar` | **0.96** |
| **Rate** | 3–7 个 star icon 子节点 + 至少 1 个 `[0-5]` 数值 | **0.94** |
| **Divider** | 细长 SVG / Line / Rectangle + 名字含 `divider` / `separator` / `line` | **0.92** |
| **Link** | 节点 / 属性含 `href` / `url` / `http://` 等 | **0.92** |
| **TagInput** | 自命名 `taginput`，或 `hasvalue` variant + 内含 Select + TagGroup | **0.95** |
| **Select（component set）** | componentSet 名 = `select` + trigger shell + `chevron` / `tag` / `+N` 等 | **0.94** |
| **Input（AI）** | input signal + AI activation | **0.94** |
| **Input.TextArea / InputNumber / InputTag / Upload** | 各自专属 signal + AI activation | **0.94** |
| **Dropdown** | 含 `dropdown menu` / `cell` / `.dropdown menu cell` | **0.92** |
| **SimpleMetricCardGroup** | 后代含 `01Metric Card` / `Metric Card` ≥ 2 次 | **0.92** |
| **Dataviz Charts**（BarChart / PieChart / WaterfallChart / Trend） | name / component 命中 + 结构规则命中 | **0.92** |
