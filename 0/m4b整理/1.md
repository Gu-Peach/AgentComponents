## 设计模式
### 1.工厂模式
定义 : 用一个函数/类"生产"多个具有相同接口的对象 ,工厂模式的本质 : 同一个"创建函数", 通过不同参数, 产出 具有相同接口但内部行为不同的对象。

核心函数 : createFigmaToDesignSystemTool (632 行)

文件 : design-systems/tools/create-figma-to-design-system-tool.ts

```ts
// 工厂函数
export function createFigmaToDesignSystemTool(config: {
  id: string;
  description: string;
  adapter: DesignSystemAdapter;
  outputField: string;
  enableCachedResult?: boolean;
}) {
  return createTool({
    id: config.id,
    description: config.description,
    inputSchema: ...,
    outputSchema: ..., 
    execute: async ({ context }) => {
      // 632 行的通用推断逻辑
      // 使用 config.adapter 做特化
    },
  });
}

// 传不同参数 → 产出不同对象
const toolA = createFigmaToDesignSystemTool({ adapter: m4bAdapter });
const toolB = createFigmaToDesignSystemTool({ adapter: hiuiAdapter });

// toolA 和 toolB:
// ✅ 相同接口 (都是 Mastra Tool, 都有 execute 方法)
// ✅ 相同签名 (都吃 figmaUrl, 都吐 yaml)
// ❌ 不同行为 (内部用不同 adapter)
```

这里的"暴露"是"配置项", 不是"内部实现" 。
调用方看到的是:
```ts
// 调用方
const figmaToM4bComponents = createFigmaToDesignSystemTool({
  id: 'figma-to-m4b-components',
  description: '...',
  adapter: m4bDesignSystemAdapter,
  outputField: 'm4bYamlResult',
  enableCachedResult: true,
});
```



### 2.适配器模式
定义 : 把"通用输入"适配到"特化输出" ——同一个通用接口, 不同的具体实现桥接到不同的底层能力。实际上就是包装成同一接口形式

核心角色 :

- 接口 : 定义"通用能力"
- 适配器 : 把"具体实现"包装成"符合通用接口"的形式
接口 (抽象) :
```ts
interface DesignSystemAdapter {
  id: 'm4b' | 'hiui';
  componentSignatures: Signature[];
  detectComponentCandidates: (payload: FigmaLikePayload) => DetectionResult;
  iconMatcher: IconMatcher;
  agent: { promptKey: string };
  resolveReferenceDocs: (context) => Docs;
  // ...
}


// 适配器 1: 把 "m4b 的具体识别方式" 适配到通用接口
const m4bDesignSystemAdapter: DesignSystemAdapter = {
  id: 'm4b',
  detectComponentCandidates: (payload) => 
    detectFigmaComponentCandidates(payload, figmaComponentSignatures),  // ← 桥接
  iconMatcher: m4bIconMatcher,
};

// 适配器 2: 把 "hiui 的具体识别方式" 适配到通用接口
const hiuiDesignSystemAdapter: DesignSystemAdapter = {
  id: 'hiui',
  detectComponentCandidates: (payload) => 
    detectFigmaComponentCandidates(payload, hiuiComponentSignatures),  // ← 桥接不同签名库
  iconMatcher: hiuiIconMatcher,
};
```

## 3.策略模式
定义 : 多个对象用同一个接口定义, 然后实际调用是 通过"接口引用"调用具体对象 —— 调用方持有的变量是接口类型, 不知道具体是哪个对象
```ts
// 调用方拿到的是接口类型的引用, 不知道具体是谁
function execute({ context }) {
  const adapter: DesignSystemAdapter = context.designSystemAdapter;
  //             ^^^^^^^^^^^^^^^^^^^^^
  //             类型是接口, 不是具体对象
  
  adapter.detectComponentCandidates(payload);  
  //   ↑
  //   编译时: 调的是"接口方法"
  //   运行时: 具体是哪个对象决定的
}

// 传入不同对象, 运行时决定
execute({ context: { designSystemAdapter: m4bAdapter } });   // 运行时是 m4b
execute({ context: { designSystemAdapter: hiuiAdapter } });  // 运行时是 hiui
```

```ts
// 策略接口
interface CalculationStrategy {
  calculate(a: number, b: number): number;
}

// 多个策略 (每个策略是一个对象)
const addStrategy: CalculationStrategy = { calculate: (a, b) => a + b };
const subStrategy: CalculationStrategy = { calculate: (a, b) => a - b };
const mulStrategy: CalculationStrategy = { calculate: (a, b) => a * b };

// 使用者
function useCalculator(strategy: CalculationStrategy, a: number, b: number) {
  return strategy.calculate(a, b);  // ★ 通过接口调用, 不知道具体策略
}

// 运行时切换策略
useCalculator(addStrategy, 1, 2);   // 3
useCalculator(mulStrategy, 3, 4);   // 12
```

```ts
// ============================================================
// 1. 策略接口 = DesignSystemAdapter
// ============================================================
interface DesignSystemAdapter {
  /** 设计系统 ID, 用于运行时判别 */
  id: 'm4b' | 'hiui' | 'pulse';
  
  /** 组件签名库 (Table/Popover/... 长什么样) */
  componentSignatures: FigmaComponentSignature[];
  
  /** 组件识别函数: Figma 节点树 → 候选组件 */
  detectComponentCandidates: (
    payload: FigmaLikePayload
  ) => FigmaCandidateDetectionResult;
  
  /** 图标匹配器 */
  iconMatcher?: {
    annotateResolvedIconsInPayload: (payload: FigmaLikePayload) => void;
    collectMatchedIconsFromPayload: (payload: FigmaLikePayload) => MatchedIcon[];
  };
  
  /** 引用文档解析 (拿 60+ 个 m4b 组件的 markdown 说明给 LLM 参考) */
  resolveReferenceDocs: (
    context: DesignSystemContext
  ) => Promise<ReferenceDoc[]>;
  
  /** Agent 配置 (指向 Fornax 上的 prompt) */
  agent: {
    promptKey: string;  // 例如: 'gec.ai.m4b_d2c'
  };
  
  /** 重复结构归一化 (hiui 特有) */
  repeatedStructureNormalization?: {
    enabledByDefault: boolean;
  };
}

// 2. 多个策略对象
// ============================================================

// ─── m4b 策略 ────────────────────────────────
const m4bAdapter: DesignSystemAdapter = {

// 兜底逻辑 (来自源码 L38-43)
function getDesignSystemAdapterFromContext(
  context: unknown
): DesignSystemAdapter {
  return (
    (context as { designSystemAdapter?: DesignSystemAdapter } | undefined)
      ?.designSystemAdapter ?? m4bAdapter  // ← 忘了传就用默认 m4b
  );
}

async function execute({ 
  input, 
  context 
}: {
  input: { figmaUrl: string };
  context: { designSystemAdapter?: DesignSystemAdapter };
}) {
  // ─── Step 1: Figma REST 拉子树 ───
  const { fileKey, nodeId } = parseFigmaUrl(input.figmaUrl);
  const rawApiResponse = await figmaService.getRawNode(fileKey, nodeId);
  
  // ─── Step 2: 剪枝简化 ───
  const simplifiedDesign = simplifyRawFigmaObject(rawApiResponse, allExtractors);
  
  // ─── Step 3: ★ 运行时决定用哪个策略 ───
  const adapter = getDesignSystemAdapterFromContext(context);
  
  // ─── Step 4: ★ 通过接口调用 (不知道具体是 m4b/hiui/pulse) ───
  const candidateDetectionResult = adapter.detectComponentCandidates(
    simplifiedDesign
  );
  
  // ─── Step 5: 用 adapter 的其他能力 (图标匹配) ───
  adapter.iconMatcher?.annotateResolvedIconsInPayload(simplifiedDesign);
  
  const matchedIcons =
    adapter.iconMatcher?.collectMatchedIconsFromPayload(simplifiedDesign) ?? [];
  
  // ─── Step 6: 后续处理省略 (assets / 复合结构识别 / 序列化) ───
  
  return {
    figmaNodeData: yaml.stringify(simplifiedDesign),
    candidateComponents: candidateDetectionResult.components,
    candidateNodes: candidateDetectionResult.nodes,
    matchedIcons,
  };
}
```
