设计hover组件，通过监听onMouseEnter，onMouseLeave等事件，React Portal 挂到 document.body + z-index 3000 的组合实现。触发跨父容器渲染（浮在 所有父容器之上 ，避免被 overflow: hidden 裁剪）。setTimeout设计防抖和延迟关闭

为什么不用 CSS :hover ：

- CSS 无法把浮层挂到 body（会被父容器裁）
- CSS 无法做防抖 / 延迟关闭
- CSS 无法支持"从 trigger 移到 popover 之间不关闭"
- CSS 无法被 JS 命令式控制

## 埋点
特定时机上报事件到数据服务器
包括声明式埋点和命令式埋点
接触到较多的是曝光埋点和点击事件埋点
### 声明式埋点
使用data-btm属性，映射曝光码，
以BtmSDK 为例：
```
// BTM SDK 简化伪代码
class BtmSDK {
  init() {
    // 1. 用 MutationObserver 监听 DOM 变化
    const observer = new MutationObserver(this.scanDom);
    observer.observe(document.body, { childList: true, subtree: true });
    
    // 2. 用 IntersectionObserver 监听曝光（元素进入视口）
    this.intersectionObserver = new IntersectionObserver((entries) => {
      entries.forEach((entry) => {
        if (entry.isIntersecting) {
          // ⭐ 元素进入视口 → 上报曝光
          const btm = entry.target.getAttribute('data-btm');
          const config = JSON.parse(entry.target.getAttribute('data-btm-config'));
          this.reportExpose(btm, config.params);
        }
      });
    });
    
    // 3. 全局点击代理（事件委托）
    document.addEventListener('click', (e) => {
      const btmEl = e.target.closest('[data-btm]');
      if (btmEl) {
        const btm = btmEl.getAttribute('data-btm');
        // ⭐ 触发点击上报
        this.reportClick(btm);
      }
    });
  }
  
  scanDom = () => {
    // 找到所有带 data-btm 的 DOM 节点
    document.querySelectorAll('[data-btm]').forEach((el) => {
      this.intersectionObserver.observe(el);  // 注册曝光监听
    });
  };
}
```

#### 实现方法
封装useEnableNewPriceDiagnosisBenefits hook来让AB实验开关消费，根据分组展示不同的组件
useEnableNewPriceDiagnosisBenefits原理：
从实验平台（Libra）拉取当前用户的分组结果值 variant，异步 setState 翻译成布尔并触发重渲染，输出布尔值，让消费方通过三元表达式在新旧组件间切换。
**AB Hook 定义**：

```ts
// experiments.ts
// 从 priceDiagnosisBenefitsExperiment.ts 引入实验常量对象。这个常量对象里有三个字段：

// - KEY ：Libra 平台上注册的实验唯一标识，字符串（ 'enable_new_price_diagnosis_benefits' ）
// - CONTROL_VALUE ：对照组的取值（如 '0' ）
// - TREATMENT_VALUE ：实验组的取值（如 '1' ）
// 为什么单独抽常量？ 避免魔法字符串 + 让 hook / 消费方 / 测试代码指同一个 source of truth。
import { useEffect, useState } from 'react';
import { getLibraVars } from '@oec-seller/sdk/utils/tea';
import { useAbConfigStore } from '@/shared/hooks/useSeaAbTest/abConfigStore';
import {
  PRICE_DIAGNOSIS_BENEFITS_EXPERIMENT_CONTROL_VALUE,
  PRICE_DIAGNOSIS_BENEFITS_EXPERIMENT_KEY,
  PRICE_DIAGNOSIS_BENEFITS_EXPERIMENT_TREATMENT_VALUE,
} from '@/shared/constants/priceDiagnosisBenefitsExperiment';

// 判断 Libra 返回值是否命中实验组
export const isPriceDiagnosisBenefitsExperimentValueEnabled = (
  value: unknown,
) =>
  String(value ?? PRICE_DIAGNOSIS_BENEFITS_EXPERIMENT_CONTROL_VALUE) ===
  PRICE_DIAGNOSIS_BENEFITS_EXPERIMENT_TREATMENT_VALUE;

export const useEnableNewPriceDiagnosisBenefits = () => {
  // 1. 等待全局 AB 配置就绪（避免首屏拿到脏值）
  const isAbConfigReady = useAbConfigStore(state => state.isReady);
  // 2. 用本地 state 缓存分组结果，供组件订阅
  const [enabled, setEnabled] = useState(false);

  useEffect(() => {
    if (!isAbConfigReady) return;

    let isMounted = true;

    // 3. 命令式向 Libra 拉分组值（异步 callback），拿到后翻译成布尔
    getLibraVars(
      PRICE_DIAGNOSIS_BENEFITS_EXPERIMENT_KEY,
      PRICE_DIAGNOSIS_BENEFITS_EXPERIMENT_CONTROL_VALUE, // 兜底：Libra 未就绪时视为对照组
      value => {
        if (!isMounted) return; // 组件已卸载 → 丢弃回调，防止 setState 泄漏
        setEnabled(isPriceDiagnosisBenefitsExperimentValueEnabled(value));
      },
    );

    // 4. 清理：卸载时置位 flag，屏蔽掉此后到来的 Libra 回调
    return () => {
      isMounted = false;
    };
  }, [isAbConfigReady]);

  return enabled;
};
```

**AB 开关消费**：

```tsx
const enableNewBenefits = useEnableNewPriceDiagnosisBenefits();
const isPriceDiagnosisEnabled = REGION_CONFIG.priceDiagnosis?.enabled;

}

```


## 首页价格组件
MF（Module Federation）和 Dynokit 都是"跨应用共享组件"的方案，但一个偏"构建期契约 + 运行时联合"（通过宿主的构建配置暴露出去），一个偏"独立打包 + CDN 分发 + 平台注册"。前者服务于 同域内主子应用共享代码**，后者服务于 跨业务线的插件式挂载 。**
MF：组件是 通过宿主的构建配置暴露出去 的（配置在 mf.config.js 里）
```
exposes: {
  './PriceOperationWidget': './src/applications/submodule/entries/PriceOperationWidgetNew/index.tsx',
  // ... 其他 6 个 exposes
}
```
用途 ：主要是 同一个组织内 （ @shop/product 团队自己维护），把大应用拆成多个可复用模块，让别的应用（比如首页）能"引用"到这个 apps/product 里的组件。

- Dynokit ：每个 Widget 是独立 bundle，消费方引入的是 Dynokit SDK （不是 Widget 本身），SDK 根据 widgetId 到 Dynokit 平台 查真实 URL 再运行时 fetch。
- MF ：消费方在 build config 里注册 远端清单入口 （ remoteEntry.js URL），运行时通过 Webpack runtime 按 remoteName/exposedKey 路径去清单里查模块，再拉实际 chunk。

```tsx
function useCountDown({ targetDate, interval }) {
  const [countdown, setCountdown] = useState(
    Math.max(targetDate - Date.now(), 0)
  );

  useEffect(() => {
    const timer = setInterval(() => {
      const remaining = Math.max(targetDate - Date.now(), 0);
      setCountdown(remaining);
      if (remaining === 0) clearInterval(timer);
    }, interval);

    return () => clearInterval(timer);
  }, [targetDate, interval]);

  return [countdown];
}
```

# 提效工具
## D2C skills(组件推断工具+skills)
为了解决figma MCP 解析出来的巨型figma会占用大量上下文，模型出现遗忘/ 幻觉等现象，并且偷懒使用原生html的情况。创建figmaToM4bComponents候选组件，用skills引导强制回归组件库 。


遍历原始figma结构树，按层级获取每一个节点的类型，边界，padding，color,字体大小等信息。然后根据节点类型映射到外层容器选型（是组件还是元素），并给出具有层级结构的yaml，有引用图片的临时生成S3 URL。服务输出yaml给agent然后转化成react组件。

1️⃣ Figma REST 拉子树
    你的 agent → MCP → api.figma.com/v1/files/<key>/nodes?ids=<id>
    输入: figmaUrl
    输出: Figma JSON (原始节点树)

2️⃣ 服务端内部推断 (规则 + LLM)
    ────────────────────────────
    规则层做 (60~80%):
        - 递归遍历
        - INSTANCE → 匹配 m4b 业务组件
        - FRAME auto-layout → Flex
        - TEXT → element: p/span
        - IMAGE/VECTOR → element: img + 切图
        - Figma style → Tailwind className (Pulse token 映射)
        - layout 参数 → Flex props

    LLM 层做 (20~40%, 但耗时 90%):
        - 纯 FRAME 该选 Container 还是 Flex (灰色地带)
        - meta.description 语义描述
        - 全局一致性决策

    输出: yaml (已经是 JSX 树结构)

3️⃣ 服务端返回 MCP 响应
    { m4bYamlResult, candidateComponents, required }
    ↓ 通过 MCP 协议返回给你的 agent

4️⃣ Agent 落地成 React (无 LLM 或轻量 LLM)
    ────────────────────────────
    你的 agent (Codex/Claude) 读 yaml:
        - 拿 imports 段 → 写 import 语句
        - 拿 root 段 → 遍历树, 照抄成 JSX
          - component: X → <X ...props>
          - element: p → <p ...props>
          - children: [...] → 递归展开
    
    附加动作 (SKILL.md Hard Gate 要求):
        - 每个 component 查 m4b-design-component skill 核对 props
        - 避免 LLM 幻觉的 props
    
    输出: .tsx 文件

实际工作链路：
```
figma (整页/大区)
    ▼
detectFigmaLayoutBlocksTool  ← 只拆布局，不做组件推断
    │  返回 blocks[] (含 name / bounds / childBlockIds / layoutMode)
    ▼
挑"组件级 block"（叶子 / 语义块 / 名字含 Table/Chart/Filter 等）
    ▼
对每个组件级 block:
  ├─ figmaToM4bComponents  ← 这才是真正的"figma→组件推断"
  │    返回:
  │      • m4bYamlResult       (完整技术栈契约 + assets)
  │      • candidateComponents (真实组件名: Table / DatePicker / Tabs...)
  │      • required            (强制提示"必须查 m4b-design-component")
  └─ getFigmaImageTool         (人眼参考图)
    ▼
candidateComponents → 查 m4b-design-component skill 核对真实 props
    ▼
产出【组件契约 Component Contract】← 硬门槛，没契约不许写代码
    ▼
按 yaml.target (react / ts / tailwind / @m4b-design/components) 写代码
    ▼
浏览器验证 DOM 出现 pulse-table / core-table / pulse-tabs 等真实组件
```
