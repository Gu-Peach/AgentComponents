# 工业三维可视化仿真平台
## 功能对标与颠覆性创新白皮书

**对标系统**：Visual Components Premium 4.8  
**文档版本**：v1.0 · 2026-04  
**文档性质**：产品定位与技术差异化说明

---

## 概述

Visual Components 4.8（以下简称 VC 4.8）是目前工业领域主流的三维工厂仿真软件，广泛应用于制造业数字孪生、产线规划和机器人编程。本平台在完整复刻 VC 4.8 核心工作流的基础上，将其中依赖专业工程师手动配置的环节替换为 LLM-Agent 驱动的智能化流程，实现从"专家工具"向"智能平台"的跨越。

本文档分两部分：一、对标实现的功能（忠实复刻）；二、颠覆性创新（根本性替换）。

---

## 第一部分：对标 VC 4.8 实现的功能

### 1. 电子目录（eCatalog）

#### VC 4.8 的实现

VC 4.8 的电子目录是一个多源设备库面板，支持从本地文件夹、远程 URL（XML 索引文件）加载设备模型。用户可通过收藏夹、Smart Collection（基于元数据查询的动态集合）、按类型/制造商分类等方式组织和检索超过 3500 个预定义组件。目录树与缩略图网格并列显示，支持拖拽模型进入 3D 场景。

#### 本平台的复刻实现

本平台完整复刻了 eCatalog 的核心交互范式，并迁移为 Web 原生实现：

**目录树结构**对应 VC 的收藏夹层级，包含：所有模型、公共模型（Components 子文件夹 + Layouts 子文件夹）、我的模型、当前打开、最近模型、最常使用的、按类型分类、按制造商分类。树节点使用 `@radix-ui/react-collapsible` 实现折叠交互，与 VC 行为一致。

**缩略图网格**对应 VC 的组件预览区，使用 `@tanstack/react-virtual` 实现虚拟化渲染，支持数百条设备在不卡顿的情况下流畅展示。

**搜索功能**通过后端 PostgreSQL 的 `pg_trgm` 全文索引实现模糊匹配，支持中英文设备名称搜索，结果带 Redis 缓存（TTL 300 秒）。

**拖拽入场**复刻了 VC 的核心交互——将设备从目录拖入 3D 场景自动放置。技术实现上使用 HTML5 原生 drag 传递 `deviceId`，React Three Fiber Canvas 的 `onDrop` 接收后通过 Raycasting 与地板平面求交，将屏幕坐标转换为世界坐标，与 VC 的拖放体验一致。

**布局文件夹**对应 VC 的 Layouts 集合，存储预设的完整车间布局方案（包含设备引用索引、拓扑关系、工作流描述），用户可将整个布局拖入场景一键实例化所有设备。

---

### 2. 布局配置（Layout Configuration）

#### VC 4.8 的实现

VC 4.8 的布局配置是用户搭建车间场景的核心工作区。用户在 3D 世界中摆放设备、调整位置、配置组件间的连接（Port 连接），并通过组件属性面板修改设备参数。支持多选操作、CAD 文件导入（STEP/IGES 等格式）、子布局（Sub-Layout）管理复杂场景。

#### 本平台的复刻实现

**三面板工作区**复刻了 VC 的布局编辑环境：左侧 eCatalog 面板、中间 3D 视口、右侧属性面板，使用 `react-resizable-panels` 实现任意调整宽度，底部增加终端面板对应 VC 的输出窗口。

**场景持久化**使用 MongoDB 存储完整场景文档（`SceneDocument`），包含所有设备实例的位姿、参数和工艺配置。每次编辑通过 JSON Patch（RFC 6902）原子更新，配合 `version` 字段做乐观锁防止并发冲突。

**设备实例管理**对应 VC 的组件实例系统：每个从目录拖入的设备生成唯一 `instance_id`，保存完整的 `default_params`（对应 VC 默认 Tab 参数）和 `simulation_params`（对应仿真参数），设备间通过 `connections` 记录物流流向关系。

**多人协作编辑**扩展了 VC 单机版的局限，通过 WebSocket 实现同一项目内多用户实时协同编辑，任意用户的设备移动、参数修改操作实时广播给所有在线成员。

---

### 3. 三维操作（3D World）

#### VC 4.8 的实现

VC 4.8 的 3D 视口是工业级三维交互环境。支持右键旋转（Orbit）、左右键平移（Pan）、滚轮缩放（Zoom），以及 SetCOI（设置旋转中心）等精细操作。场景内可进行矩形区域多选、按 Tab 切换选中对象。TransformControls 支持平移/旋转/缩放三种变换模式，支持世界坐标系与局部坐标系切换。

#### 本平台的复刻实现

**轨道控制**使用 `@react-three/drei` 的 `OrbitControls`，完整支持旋转/平移/缩放三种交互，鼠标按键映射与 VC 保持一致。

**变换操控器**（Transform Gizmo）在选中设备时显示三色坐标轴控制柄，支持平移（T）/ 旋转（R）/ 缩放（S）模式切换，对应 VC 的 Manipulation group 功能。

**网格地板**（GridFloor）对应 VC 的 Floor 和 Grid 显示，默认显示 50m × 30m 区域，1m 间距，可配置显隐。

**坐标系统**复刻 VC 的三种坐标系切换——世界（World）、父系坐标（Parent）、物体（Local），在属性面板的坐标 Widget 中提供单选切换，X/Y/Z 和 Rx/Ry/Rz 六维输入与 VC 属性面板完全对应。

**Cell Graph**（设备树图）对应 VC 的 Cell Graph 面板，以树形列表展示场景中所有设备实例，支持通过列表选中、隐藏、锁定难以在 3D 视口中点击到的设备。

---

### 4. 组件属性面板（Component Properties）

#### VC 4.8 的实现

VC 的属性面板在选中组件时显示该组件的所有可配置属性，分为三个 Tab：默认（基础参数和业务参数）、Advanced（内部结构参数）、Materials（材质配置）。面板顶部显示组件名称和坐标信息（支持世界/父/物体坐标系切换）。不同类型组件的默认 Tab 显示各自特有的参数字段（如传送带显示 ConveyorLength/Width/Height/Speed，升降台显示 CarrierAmount 等）。

#### 本平台的复刻实现

**面板整体结构**对标 VC：顶部设备标题栏（显示名称和类型）→ 坐标区（固定，不随 Tab 切换）→ 参数 Tab 区域。

**Tab 结构调整**：本平台根据设备规范将 Tab 简化为"默认"和"仿真"两个 Tab（原 VC 的 Advanced 参数合并到仿真 Tab 中与仿真相关的参数），Materials Tab 作为后期扩展。

**四类设备参数字段完整对应**：

| 设备类型 | 默认 Tab 字段 | 仿真 Tab 字段 |
|---|---|---|
| 传送带 | 名称/类别/ConveyorLength/Width/Height/Speed/LiftOffset | StartOffset / EndOffset |
| 机械臂 | 名称/类别 | speed + 6 轴关节折叠列表（nodeName/axis/limit） |
| 升降台 | 名称/类别/nodeName/carrierNodeName | rootAxis/carrierAxis/rootRange/carrierRange/speed |
| 仓储柜 | 名称/类别 | 货格卡片网格（id + XYZ 坐标，支持增删） |

**动态表单渲染**：参数字段由后端 MongoDB `device_specs` 集合中的 `default_params` 结构驱动，前端无硬编码字段，新增设备类型只需在数据库插入规范文档，面板自动适配。

### 5. 仿真控制（Simulation Controls）

#### VC 4.8 的实现

VC 的仿真控制条位于 3D 视口顶部中央，提供播放（▶）、暂停（⏸）、停止（⏹）、重置按钮，时间显示（HH:MM:SS），以及速度倍率控制（0.1x 至 10x）。仿真运行时设备按配置的行为参数动态运动。仿真结果可通过 Statistics 行为导出 CSV。

#### 本平台的复刻实现

**仿真控制条**以透明浮层形式覆盖在 3D 视口顶部中央，包含：重置（⏮）、播放/暂停切换（▶/⏸）、停止（⏹）、时间显示（HH:MM:SS 格式，`\x1b[33m` 黄色字体对应 VC 风格）、速度倍率下拉（0.1 / 0.5 / 1.0 / 2.0 / 5.0 / 10.0）。

**仿真状态管理**：播放/暂停/停止触发 API 调用，后端通过 Celery 控制 SimPy 仿真进程，状态同步到 Redis `sim:state:{project_id}` Hash，前端通过 WebSocket 实时更新控制条显示。

**帧数据驱动动画**：仿真运行时 SimPy 每 0.1 仿真秒生成一帧，通过 Redis Stream → WebSocket → 前端，驱动 3D 场景中各设备节点的位置和关节角度实时更新，对应 VC 的仿真动画效果。

**统计输出**对应 VC 的统计导出功能，在终端面板输出各设备的利用率、处理件数、等待时间，仿真结束后提供 OEE 和瓶颈分析摘要。

---

### 6. 输出终端（Output Panel）

#### VC 4.8 的实现

VC 的输出窗口位于界面底部，实时显示布局加载日志（读取模型文件、解析组件、加载几何节点等带缩进的日志信息）和仿真过程中的 Python Script print 输出。日志包含文件路径、节点 ID 等详细信息，是调试设备配置的重要工具。

#### 本平台的复刻实现

**终端面板**使用 `ansi-to-html` 库渲染 ANSI 颜色码，支持与 VC 一致的日志格式：带缩进的层级读取日志、设备节点名称高亮显示。

**日志来源**扩展为三类：布局加载日志（设备文件读取、参数解析）、Agent 调度日志（蓝色，显示 Agent 的场景分析和计划生成过程）、SimPy 仿真运行日志（绿色时间戳 + 设备事件）。

**自动滚底**：新日志到来时自动滚动到底部，与 VC 输出窗口行为一致。支持手动清除日志。

## 第二部分：颠覆 VC 4.8 的创新

### 核心颠覆逻辑

VC 4.8 是"专家工具"——设备的工艺行为（Process Modeling）和仿真逻辑（Python Script Behavior）需要由具备编程能力的仿真工程师手动配置。学习曲线陡峭，建模周期长，设备行为逻辑与场景强耦合，复用困难。

本平台的颠覆集中在两个环节：**工艺建模** 和 **仿真调度**，将其从手动配置替换为 LLM-Agent 驱动的智能化流程。

---

### 颠覆点一：工艺建模（Process Modeling）

#### VC 4.8 的方式

在 VC 4.8 中，为设备添加工艺行为需要：

1. 切换到 Modeling 标签页
2. 手动添加 Python Script Behavior
3. 在脚本编辑器中编写 Python 代码定义设备逻辑（OnRun 事件、阻塞函数、信号连接）
4. 添加 Path Behavior 定义物料传输路径
5. 通过 Port 连接设备间的物流关系
6. 在 Process Modeling 面板中定义 Flow → Product → Statement 三层工艺流程

这个过程需要熟悉 VC 的 Python API、组件行为系统、信号机制，专业门槛高，每台设备的建模时间从数小时到数天不等。

#### 本平台的颠覆

**用自然语言对话替代手动脚本编写**。用户在 AI 聊天面板输入工艺意图，Agent 自动完成整个建模过程：

**Agent 工作流**（LangGraph 状态机）：

```
用户输入「让升降台以 0.8m/s 将传送带出口的物料送到仓储柜 A2 格位」
    │
    ▼
Resolver Node（意图解析）
    识别：操作类型 = configure_device，目标 = smart_storage_1，工艺 = 升降台取放料
    │
    ▼
Skill Router Node（设备类型路由）
    查询 MongoDB device_specs，确定 device_type = "lift"
    从 Skill 注册表加载 LiftSkill
    │
    ▼
Device Modeler Node（工艺配置生成）
    调用 LiftSkill.build_prompt()，将 device_spec 规范注入 Prompt
    LLM with structured_output 生成 process_config：
    {
      "behaviors": [{
        "type": "deliver",
        "speed": 0.8,
        "source": "conveyor_1.exit",
        "target_cell": "A2",
        "target_instance": "storage_01"
      }],
      "states": ["idle", "moving_x", "moving_y", "placing", "done"],
      "signals": { "input": ["part_ready"], "output": ["place_done"] }
    }
    │
    ▼
Guardian Node（合法性校验）
    JSON Schema 校验：speed 0.8 在 [0.05, 2.0] m/s 范围内 ✓
    业务规则校验：A2 格位坐标在 carrierRange 内 ✓
    │
    ▼
Scene Patcher Node（写入场景）
    JSON Patch 更新 MongoDB scenes 文档
    WebSocket 广播 process_config_updated 事件
    前端属性面板仿真 Tab 实时更新
```

**Skill 规范系统**（可复用的建模规范）：

每类设备对应一个 Skill，包含三个组成部分：

1. **Prompt 模板**：将设备规范约束注入 LLM，告知合法参数范围、业务规则
2. **业务规则校验**：Schema 校验之外的逻辑（如升降台目标格位必须在 carrierRange 内）
3. **结构化输出 Schema**：Pydantic 模型定义 LLM 输出格式，保证 JSON 结构合法

Skill 一旦定义完成，可跨场景、跨项目复用。新增设备类型只需新增一个 Skill，无需修改 Agent 框架。

**对比优势**：

| 维度 | VC 4.8 手动建模 | 本平台 Agent 建模 |
|---|---|---|
| 用户门槛 | 需懂 Python + VC API | 自然语言描述即可 |
| 单台设备建模时间 | 数小时至数天 | 秒级响应 |
| 建模规范一致性 | 依赖工程师经验，各不相同 | Skill 强制约束，规范统一 |
| 参数合法性保障 | 运行时报错才发现 | Guardian 节点提前校验 |
| 跨场景复用 | 手动复制脚本 | Skill 注册表自动复用 |
| 修改迭代 | 改代码，调试运行 | 对话追加说明，秒级重新生成 |

### 颠覆点二：仿真调度（Simulation Orchestration）

#### VC 4.8 的方式

VC 4.8 的仿真是**配置驱动**的：设备的仿真行为由建模时硬编码在 Python Script 中的逻辑决定。要改变仿真场景（如改变调度策略、测试不同参数组合），需要修改 Python 脚本，重新建模，再运行仿真。仿真参数与仿真逻辑耦合在一起，无法动态调整。

仿真顺序由 Process Modeling 的 Flow 定义，静态固定，不支持基于当前运行状态的动态调度。

#### 本平台的颠覆

**AI 调度层 + SimPy 执行层严格分离**，实现了"智能调度，动态仿真"。

**架构对比**：

```
VC 4.8：
    场景建模（Python Script）──── 仿真运行
    仿真逻辑硬编码在设备脚本中，参数与逻辑耦合

本平台：
    AI 调度层（LangGraph Agent）
        │  生成 SimPlan JSON（两层之间唯一接口）
        ▼
    SimPy 执行层（轨迹算法 + 事件驱动）
        仿真逻辑与参数完全解耦
```

**SimPlan 是两层之间的契约**，包含：每个设备使用哪个轨迹算法、以什么参数运行、以及设备间的协调规则（信号触发、资源等待）。Agent 只负责生成这份计划，SimPy 只负责执行，互不依赖。

**Agent 的五层调度能力**：

Agent 能够理解从简单到复杂的五种用户输入层级，并生成对应的仿真计划：

**Level 1 — 极简指令**：「跑一下仿真」
Agent 自动读取 scene.json 的 workflow 和 topology，从 device_specs 取默认参数，生成完整的 SimPlan，用户零配置。VC 4.8 中同等操作需要所有设备已预先配置好 Python Script。

**Level 2 — 参数覆盖**：「传送带速度 400mm/s，仿真 30 分钟」
Agent 提取用户给出的参数，覆盖默认值，其余参数读配置文件自动填充。VC 4.8 需要用户手动找到对应设备的属性面板，逐一修改参数，再重新运行。

**Level 3 — 工艺逻辑**：「高峰期场景，仓储柜满后升降台 2 先出库最老的物料，再允许继续入库」
Agent 生成带条件分支的协调规则（`resource_wait` + LIFO 出库策略），这类动态调度逻辑在 VC 4.8 中需要编写复杂的状态机 Python 脚本，且难以复用。

**Level 4 — 文档驱动**：用户上传包含设备参数表、入库/出库规则、验收标准的 Markdown 文档
Agent 解析文档结构，将验收标准转化为 SimPy 断言检查（如吞吐量 ≥ 400 件/小时），在仿真过程中实时检验，仿真结束后输出是否达标。VC 4.8 不支持此类测试驱动的仿真验证。

**Level 5 — 多轮迭代**：基于仿真结果对话调整参数，命名保存仿真方案
Agent 通过 `MemorySaver` 维护多轮对话状态，支持「上次仿真瓶颈在仓储柜，把格子增加到 9 个，重新跑」这类增量修改。VC 4.8 的每次参数调整需要手动在 GUI 中修改，无法记录和复现调参历史。

**Human-in-the-loop 追问机制**：

当用户输入缺少关键参数时（如指定了仿真时长但未指定升降台速度），Agent 在 `clarifier_node` 中断图执行，向前端推送追问消息，等待用户补充后恢复执行。VC 4.8 遇到参数缺失会使用默认值静默执行，用户无感知，容易产生误导性结果。

### 颠覆点三：Web 原生架构

#### VC 4.8 的方式

VC 4.8 是 Windows 桌面软件，需要安装，单机使用，项目文件以 `.vcmx` 格式存储在本地。协作需要通过文件传输，无法多人实时编辑同一场景。许可证基于设备绑定，并发使用受限。

#### 本平台的颠覆

**全 Web 化**：浏览器直接访问，无需安装，跨平台（Windows / macOS / Linux）。

**多人实时协同编辑**：同一项目内多用户可同时编辑场景，任意设备的位移、参数修改、工艺配置变更实时同步到所有在线成员，通过 WebSocket 广播 + MongoDB 乐观锁保证一致性。

**云端项目管理**：项目、设备目录、仿真方案全部云端存储，支持版本追溯，设备的建模规范（Skill）跨项目复用。

**API 开放**：平台提供完整 REST API，可与企业 MES/ERP 系统集成，将车间仿真数据回流到生产管理系统。VC 4.8 的 API 仅限 .NET 插件开发，集成复杂度高。

---

### 颠覆点四：URDF 原生支持

#### VC 4.8 的方式

VC 4.8 使用自有的组件格式（`.vcmx`）存储设备模型，支持 CAD 格式导入（STEP/IGES/OBJ 等）但不原生支持 URDF（统一机器人描述格式）。机器人运动学需要在 VC 的 Modeling Tab 中手动配置关节和 Servo Controller。

#### 本平台的颠覆

**原生 URDF 支持**：使用 `urdf-loader` 库直接加载标准 URDF 文件，机器人运动学（关节层级、轴方向、限位）从 URDF 直接读取，无需重新配置。这与 ROS 生态系统无缝衔接，用户可将 ROS 机器人描述文件直接导入平台使用。

**关节动画驱动**：仿真运行时，SimPy 的帧数据包含各关节角度值，前端通过 Three.js `getObjectByName` 找到 URDF 中对应的骨骼节点（如 `Link1_00In`、`Link2_00Jn`），直接设置旋转值，实现与 VC 机械臂动画相同的效果，但无需手动配置 Servo Controller。

## 整体对比总结

| 维度 | VC 4.8 | 本平台 |
|---|---|---|
| **用户定位** | 专业仿真工程师 | 工厂规划人员 + 工程师 |
| **工艺建模** | 手写 Python Script，专家门槛 | 自然语言描述，Agent 自动生成 |
| **仿真调度** | 静态脚本，逻辑与参数耦合 | AI 动态调度，SimPlan 解耦 |
| **建模规范** | 依赖个人经验，无统一标准 | Skill 注册表，强制规范，可复用 |
| **参数验证** | 运行时发现错误 | Guardian 节点预校验 |
| **仿真场景切换** | 修改脚本，重新建模 | 对话调整参数，秒级重新规划 |
| **协作方式** | 文件传输，单机编辑 | 实时多人协同，云端存储 |
| **机器人描述** | 自有格式，手动配置关节 | 原生 URDF，对接 ROS 生态 |
| **验收测试** | 手动查看统计，人工判断 | 文档驱动断言，自动输出达标报告 |
| **部署方式** | Windows 桌面安装包 | Web 浏览器，跨平台，无需安装 |
| **API 集成** | .NET 插件，集成复杂 | REST API，可对接 MES/ERP |
| **调参历史** | 无法记录，每次手动重做 | 多轮对话维护状态，方案命名保存 |

## 不实现的 VC 4.8 功能（当前版本范围外）

以下 VC 4.8 功能在当前版本中不实现，保留作为后期扩展：

- **机器人编程（Robot Programming）**：VC 支持离线机器人程序生成和 OLP（离线编程）导出，本平台当前仅做机器人仿真动画，不生成实际机器人程序。
- **CAD 导入（STEP/IGES）**：当前仅支持 GLB/URDF，STEP 等工程 CAD 格式的导入转换需额外开发 CAD 处理管线。
- **VR/AR 体验（VC Experience）**：VC 支持 VR 头显和点云叠加，当前不在计划范围内。
- **PDF/BOM 导出（高级格式）**：当前支持 JSON 布局导出和 CSV 统计导出，不支持 VC 的 PDF 工厂平面图导出。
- **虚拟调试（Virtual Commissioning）**：VC 支持与 PLC 实时通信（S7/OPC-UA），本平台当前为离线仿真，不对接工业控制系统。
